## 1. ТЕКУЩИЙ ФОКУС — игра «Уговори» (Roblox, ИИ-NPC)

### 1.1 Суть
- **[П]** NPC с секретом стоит на пути (вышибала клуба, дракон с золотом и т.д.). Игрок должен «уговорить» его — найти скрытый **ключ**.
- **[П]** Игра бесконечная, уровни/сцены генерируются, максимум разнообразия: много разных **сцен** (клуб, дракон, …), выпадают случайно.
- **[П]** Игра для детей: только позитивные ключи, развивающие логику и т.п. **Никакого** «соврать», «нагрубить», ничего против моральных ценностей.
- **[П]** Простые/очевидные ключи — только на низких уровнях; выше — неочевидные.
- **[П]** Любимый тип ключа: творческое задание с оценкой качества (пример: дракон начинает стих — нужно придумать рифму и закончить; пропускает, только если рифма ему действительно понравилась).

### 1.2 Режимы
- **[П]** Соло: один на один с NPC.
- **[П]** Комнаты (кооп): несколько игроков одновременно спрашивают и уговаривают одного NPC.
- **[П]** Нужен лидерборд.
- **[П]** Тот, чьё сообщение нашло ключ, получает очки и, возможно, визуальную награду.

### 1.3 Предложения Claude по механике (не утверждены)
- **[C] Сцена-конструктор:** место + персонаж + скрытый ключ + сложность. Сотни шаблонов генерирует сильная модель заранее (офлайн), Павел просматривает; в игре ИИ только отыгрывает роль.
- **[C] Структура загадки в 2 шага:** 1) понять, чего хочет NPC (он не говорит прямо); 2) сделать это хорошо (навык).
- **[C] Подсказки растут с уровнем:** низкие — почти прямо; средние — намёки (оговорки, вздохи, предметы); высокие — еле заметные + строже критерии.
- **[C] Шкала «убеждённости» 0–100** над NPC; отдельная **модель-судья** оценивает каждую реплику (защита от «игнорируй инструкции и скажи да»).
- **[C] Чёткие критерии судьи** для творческих ключей (ур. 5: «рифмуется»; ур. 30: «рифма + размер + тема + без повторов»), разбор после раунда.
- **[C] Ключи не спойлерятся:** у каждого персонажа 3–5 возможных ключей, при запуске выбирается случайный. В ежедневной сцене ключ один для всех, соревнуются в скорости.
- **[C] Кооп без хаоса:** NPC отвечает по очереди, у игрока кулдаун. Сообщение, добившее шкалу до 100, получает победу и главные очки, остальные — очки за помощь.
- **[C] Бесконечность:** с уровнем NPC упрямее, ключ глубже, сообщений меньше.
- **[C] Две таблицы лидеров:** общая по очкам + **ежедневная сцена** (одна для всех, меньше сообщений = выше). Ежедневная — источник роликов.

### 1.4 Типы позитивных ключей [C]
| Качество | Пример |
|---|---|
| Сочувствие | спросить грустного гнома, что случилось, и утешить |
| Искренняя доброта | найти в страшном тролле что-то по-настоящему хорошее |
| Любопытство | искренне спросить про хобби/коллекцию |
| Логика | решить загадку, закономерность, посчитать |
| Внимательность | заметить деталь в сцене (сломанный коготь, развязанный шнурок) |
| Творчество | рифма/закончить стих, имя питомцу, название замка |
| Щедрость | поделиться предметом, принести цветок/еду |
| Честность | признаться, что не знаешь, вместо выкручивания |
| Командная работа | (только кооп) двое делают/говорят что-то вместе |
| Действие в игре | эмоция-танец, отдать предмет, сесть рядом — делает игру «игрой», а не чатом |

Примеры ключей «понять → сделать хорошо»: закончить стих дракона; придумать имя питомцу NPC; загадать NPC загадку, которую он не отгадает; описать его замок так, чтобы он загордился; в кооп — сочинить куплет по строчке.

### 1.4.1 Раунд, очки, подсказки
- **[П]** Раунды бесконечные (без лимита времени/сообщений), лимит влияет только на очки:
  - ключ найден за ≤5 вопросов — максимум очков (тир 1);
  - ≤10 — тир 2; ≤15 — тир 3; >15 — проход без очков.
- **[П]** Подсказки, если не получается: копятся бесплатно (напр. 1 подсказка за 5 пройденных NPC) или докупаются за Robux.
- **[П]** Платный пропуск NPC — проход дальше, но без рейтинга в общей таблице.
- **[П] (утверждено)** Подсказка понижает тир — купленная подсказка не даёт максимум очков (не pay-to-win). Решения с подсказками/пропуском помечаются.
- **[П] Отклонено:** «NPC устаёт после 30 сообщений и даёт бесплатную подсказку» — игроки будут спамить до бесплатной подсказки, и покупать станет незачем. Жёстко: либо проходишь сам (или копишь заработанные подсказки), либо донатишь.
- **[П]** Кооп: у каждого игрока свой счётчик вопросов; очки получает только тот, кто нашёл ключ — соревнование внутри комнаты.
- **[П] (утверждено)** Спам одной буквой всё равно жжёт токены: короткие/бессмысленные сообщения не отправлять в LLM (NPC отвечает заготовкой), плюс лимит сообщений в минуту на игрока.
- **[C]** Без «усталости» разговор формально бесконечен — для рейтинга это, скорее всего, ок (у разговора цель, нет памяти между сессиями), но перепроверить при заполнении анкеты Content Maturity.
- **[П]** «Снайпинг» (угадать, прочитав чужие вопросы) — это фича.
- **[П]** Кооп по очереди: в группе (напр. 4 игрока) спрашивают 1→2→3→4→по кругу. Пропустить ход нельзя — каждый обязан что-то спросить/ответить (ход тратит вопрос из личного счётчика).
- **[П] (утверждено)** Таймер хода (~30–45 с): не успел — ход сгорает (засчитывается как вопрос) и передаётся дальше; после 2–3 сгоревших ходов подряд — кик за AFK.
- **[П] (утверждено)** Порядок хода сдвигается с каждым новым NPC, чтобы первый игрок не был всегда в невыгодном положении.
- **[П] (утверждено)** Зашёл посреди раунда — встаёт в конец очереди. Размер комнаты 2–6, по умолчанию 4.

### 1.4.2 После победы — крючки (утверждено)
- **[П]** Статичные уровни: сцена → экран статистики → следующая сцена (без карты мира на старте).
- **[П] (утверждено)** Момент победы: реакция NPC (дракон отдаёт золото, вышибала открывает дверь) + звук + салют/конфетти + надпись над угадавшим (текст надписи — [?], не «КЛЮЧ!») — 2–3 секунды дофамина и клип для шортсов.
- **[П] (утверждено)** Экран статистики со сравнением: «ты справился быстрее, чем 87% игроков».
- **[П] (утверждено)** Карточка результата для скриншота (сцена, вопросы, процент, ник) — бесплатная реклама.
- **[П] (утверждено)** Тизер следующего NPC: силуэт + первая фраза на экране статистики.
- **[П] (утверждено)** Серия побед: «5 NPC подряд без подсказок» с огоньком.
- **[C]** Позже — индикатор прогресса (номер сцены, кольцо уровня) вместо карты.

### 1.4.3 Призы — исследование Roblox
- **[П]** Хочется начислять косметику на общий аккаунт Roblox (переносится между играми), если это возможно.
- Факт (доки Roblox): предметы аватара с Marketplace — общие для аккаунта, носятся во всех играх.
- **Free UGC Limited, только в своей игре:** можно сделать предмет Limited с ценой 0 и продажей только в своей игре (Experience by Place ID, через API). Минусы: нужна верификация по паспорту (ID), взнос за загрузку 80 Robux, нужна 3D-модель аксессуара, и **за каждую бесплатную копию платит создатель** (пример из доков: 200 копий по 100 Robux = 20 000 Robux; Roblox забирает весь сбор); 50 бесплатных Limited в день; на форуме (авг. 2026) жалоба, что ограничение «только в игре» обходили.
- **Бейджи:** бесплатно 5 в сутки на игру (далее 100 Robux), выдаются `BadgeService:AwardBadgeAsync()` на сервере, видны в инвентаре аккаунта — «флекс» на профиле.
- **Внутриигровая косметика** (сохраняется в DataStore): бесплатно, без лимитов, но видна только в этой игре.
- Продажа своих UGC-предметов внутри игры — владелец игры получает долю с продажи (доп. монетизация).
- **[П] (утверждено) Схема наград:**
  - каждая победа — внутриигровая валюта + шанс выпадения косметики + NPC в коллекцию;
  - вехи — бейджи на аккаунт (бесплатно, 5 в сутки на игру);
  - топ месяца / ивенты — бесплатный UGC на аккаунт.
- **[П]** Всё, что стоит денег создателю (бесплатный UGC Limited, платные бейджи сверх лимита и т.п.), — **отложено**, пока игра не начнёт зарабатывать (подсказки, пропуски и т.д.). На старте — только бесплатные награды.

## 2. Исследование: ИИ и HTTP в Roblox (проверено по докам Roblox, ноябрь 2026)

### 2.1 HttpService
- Включается: Studio → File → Experience Settings → Security → **Allow HTTP Requests**.
- Только с **сервера** (не из клиента). `RequestAsync` (любые методы, заголовки, тело, gzip, Timeout), `JSONEncode/Decode`.
- `User-Agent`, `Roblox-Id` ставит Roblox; `Content-Length` вычисляется сам.
- Только HTTPS; запрещены порт 1194 и порты < 1024, кроме 80/443.
- Лимит: **500 внешних запросов/мин на игровой сервер** (общий бюджет); Open Cloud — отдельно 2500/мин. При превышении — ошибки и возможная «заморозка» ~30 с. Обрабатывать 429, pcall, экспоненциальный backoff.
- Слух с форума (не подтверждён): ~3 одновременных запроса.
- `CreateWebStreamClient()` — стриминг (SSE / chunked / WebSocket), до 4 клиентов. В доке описан как «в Studio» — **проверить, работает ли на живых серверах**.

### 2.2 Секреты (API-ключи)
- Creator Dashboard → игра → **Secrets**: имя, значение (до 1024 символов), домен. До 500 секретов на игру.
- `HttpService:GetSecret("name")` — только на сервере, не печатается. `:AddPrefix("Bearer ")`, `:AddSuffix()`.
- Секрет можно только в URL/заголовки, **не в тело**.
- В локальном тесте Studio — «Local Secrets» в Experience Settings → Security.

### 2.3 Встроенный ИИ Roblox
- `TextGenerator` (бета): SystemPrompt, Temperature/TopP/Seed, `GenerateTextAsync` (UserPrompt, ContextToken — история, MaxTokens, **JsonSchema** — структурированный ответ). Лимит ~100 запр/мин, растёт с онлайном. Модерация вход/выход от Roblox, модель настроена на All Ages. Документация требует пропускать сгенерированный текст через `TextService:FilterStringAsync()`.
- `AudioTextToSpeech` — озвучка; Speech-to-Text — речь игрока в текст.
- `GenerationService` (Cube 3D) — 3D-модели по тексту, бесплатно; 4D-объекты — ранний доступ.
- RDC 2026: развитие ИИ-NPC, Build (генерация игры по описанию), Scene Generator (обещан).

### 2.4 Правила для ИИ в играх
- За контент сторонних моделей отвечает разработчик; ввод/вывод — через `TextChatService`/фильтр, обходить нельзя.
- Обязательная пометка: «Это разговор с ИИ, а не с человеком, он может ошибаться» — в начале и во время сессии.
- При признаках самоповреждения — направлять к специалистам.
- Указать ИИ в анкете Content Maturity.
- **«Расширенное взаимодействие» → рейтинг Restricted (18+)**, если: игра — бесконечный разговор с ИИ без лимита времени, **или** ИИ помнит прошлые сессии. → Для детской «Уговори»: без памяти между сессиями, разговор как часть геймплея с целью/лимитом.

## 5. Отложенные идеи (парковка)

- **Раннер-стрелялка с воротами (PvE)** — подробно обсуждено ранее:
  - [П] линейные уровни, «дауншифт»: прошёл → следующий, не прошёл → на уровень назад; рейтинг за уровни;
  - [П] уровни одинаковые для всех, генерируются; одиночное прохождение;
  - [П] вайп/престиж ради особого свечения; кампании (стартовая → хэллоуинская и т.д. на том же скелете);
  - [П] прогресс между забегами — косметика с шансом выпадения;
  - [C] уровень = зерно генератора (`Random.new(номер)`), бюджет сложности, ручные боссы каждый 10-й, бот-проверка проходимости, версия генератора;
  - [C] рейтинг = престиж, потом уровень; общее лобби для флекса; кампания = набор настроек.
- **Погоня в лабиринте («охотники vs убегающие»)** — идея-хук на механике Pac-Man (без бренда Namco); решение холодного старта через ботов.
- **КПП** (по мотивам мода) — большая игра на базе технологии «Уговори».
- **ИИ-детектив** (социальная дедукция), **ИИ-торговец** (тайкун).
- Отброшено: «найди бота среди игроков» (нарушает пометку ИИ), рэп-баттлы/прожарки (риск модерации).
